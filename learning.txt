# 2026-07-29 — Live API comparison & correlation deep-dive findings

**Notebook**: `development/notebooks/03_live_api_comparison.ipynb`  
**Location**: Karak, Pakistan — Sabir Abad area (33.1383653° N, 71.1909136° E)  
**Original/old location**: Karak Main Bazar (33.1189° N, 71.0947° E)  
**Target time**: 6:00 PM PKT (13:00 UTC), 2026-07-29

## 1. Why the correlation was low (~0.4)

- **Timezone was the dominant cause**: Open-Meteo returns Asia/Karachi time, while
  OpenWeather returns UTC. Without normalization the two sources are shifted by
  5 hours, which misaligns the diurnal AQI cycle.
- **After timezone normalization** (last 30 days, hourly PM2.5): **r = 0.680**
- **Daily aggregation further improves** correlation to **r = 0.771**
- **Best minute-shift**: +120 min only raised r to 0.697, confirming that most of
  the improvement comes from timezone alignment, not hour-boundary offsets.
- The remaining ~0.3–0.4 unexplained variance is **expected model-to-model noise**
  because Karak has no ground station and the APIs use different atmospheric
  models / grid cells.

## 2. Live values at 6:00 PM PKT, 2026-07-29

| Variable | Open-Meteo (18:00 PKT) | OpenWeather (19:00 PKT, +60 min) |
|----------|--------------------------|----------------------------------|
| pm2_5    | 27.9 µg/m³               | 50.61 µg/m³                      |
| pm10     | 42.7 µg/m³               | 105.61 µg/m³                     |
| ozone    | 135.0 µg/m³              | 113.32 µg/m³                     |
| no2      | 3.6 µg/m³                | 2.71 µg/m³                       |
| so2      | 4.4 µg/m³                | 2.23 µg/m³                       |
| co       | 278.0 µg/m³              | 310.07 µg/m³                     |
| dust     | 28.0                     | —                                |
| uv_index | 0.3                      | —                                |

- Open-Meteo hit the target hour exactly (+0 min).
- OpenWeather forecast nearest hour was 19:00 PKT (+60 min offset), so the
  comparison is approximate.
- The two sources differ substantially on PM10 and PM2.5. This is consistent
  with model-to-model disagreement and the coarse grid over a rural/topographically
  complex area like Karak.

## 3. WAQI/AQICN sanity reference — stale data

- Station: Peshawar US Consulate, Pakistan
- WAQI AQI: 25, dominant pollutant pm25
- **Critical finding**: the reported timestamp was **2025-03-04 15:00:00**, which is
  more than four months old. The notebook flagged this as stale.
- **Implication**: WAQI/Peshawar cannot currently be relied on as a live
  validation source. Any cross-source validation should be done against
  Open-Meteo and OpenWeather only, or a different live station must be found.

## 4. What we are doing correctly

- Timezone normalization to Asia/Karachi is implemented and verified to raise
  correlation from ~0.4 to ~0.68.
- Daily aggregation is a valid strategy and raises correlation further.
- Open-Meteo is treated as the primary source; OpenWeather is used only for
  cross-validation, which is the right design.
- WAQI is treated as a sanity check only, and stale data is now flagged.

## 5. What could still be improved / potential issues

- **No ground truth**: Karak has no local monitoring station. Correlation between
  two models is not the same as model accuracy.
- **OpenWeather timestamp mismatch**: the forecast grid nearest to 6 PM PKT was
  7 PM PKT. For exact hour comparisons, use the historical endpoint for past hours
  and forecast endpoint for future hours.
- **CO units**: OpenWeather reports CO in µg/m³; many AQI standards use ppm or
  mg/m³. Any CO-based AQI must convert units first.
- **AQI derivation**: the notebook currently compares raw concentrations. The
  next step is to compute US EPA (or Pakistan EPA) AQI from each source and
  compare those.
